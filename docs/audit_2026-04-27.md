# OptiSyn 代码审计与回溯修复方案

> 审计日期:2026-04-27
> 触发原因:Stage 1 中发现 `normalized_matrix.rds` 未做 log2 转换,limma 输出的 logFC 是线性差值

## 一、Critical 问题(必须修复,否则下游全部不可信)

### C1. log2 转换系统性缺失
| 脚本 | 问题行 | 现象 |
|---|---|---|
| `scripts/step1-1_GSE31022_analysis.R` | L139 | `normalizeQuantiles` 后无 log,直接进 limma |
| `scripts/step1-1b_GSE31022_timeseries_analysis.R` | 类似 | 同上 |
| `scripts/step1-2_GSE63786_analysis.R` | L179-189 | 同上 |
| `scripts/step1-3_GSE42639_analysis_by_celltype.R` | L80-82 | 同上 |
| `scripts/step1-3_GSE42639_analysis.R / v2 / v3` | — | 同上(将归档) |
| `scripts/step4_human_data_analysis.R` (GSE185576 分支) | L52 | 仅 quantile,无 log |
| `scripts/step4_human_data_analysis.R` (GSE101702 分支) | L118 | ✅ 用 `neqc()`,该函数自带 log |

**影响**:所有 DEG 表的 logFC、阈值过滤、报告中的 DEG 计数都是线性差值,生物学不可解释。报告 01/02/04/05 中所有数字需重算。

**修复**:在每个 limma 之前加 log2 自动检测块(参考 `scripts/step2_Mo_protective_geneset_A.R` L43-56)。
